# Visual patterns

Choose the smallest combination that explains the topic. Do not use every pattern by default.

## System map

Use for three or more actors or components. Show boundaries, direction arrows, and the payload or event carried by each connection.

## Signal journey

Use when information moves through physical space or a network. Animate only to reinforce direction and timing. Include a static arrow fallback.

## Timeline

Use for synchronization, protocols, retries, buffering, or state changes. Place events on a shared time axis and call out sources of delay or uncertainty.

## Layer stack

Use when the learner must distinguish hardware, transport, operating system, API, application, and user experience responsibilities.

## Compare card

Use to correct a common misconception or contrast two approaches. Compare the same dimensions in the same order.

## Parameter playground

Use when changing one or two values reveals system behavior. Provide sensible defaults, units, constraints, and a plain-language interpretation of the result.

## Cutaway or exploded view

Use for physical devices or nested data structures. Label only parts that matter to the explanation.

## Failure-state card

Show the expected path beside one meaningful failure path. Explain detection and recovery rather than merely naming the error.

## Progressive reveal

Use when a complete diagram would overwhelm a beginner. Preserve context as detail appears; do not replace the whole diagram between steps.
